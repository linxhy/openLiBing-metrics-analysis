错误: HTTP request sent, awaiting response... 404 Not Found
根因: 测试结果元数据未发布，测试任务的下载环节被 404 挡住：测试任务装完运行依赖后，按本流水线产物地址从 openLiBing 制品库拉取 xml 结果元数据，该目录返回不存在，下载脚本非零退出，测试任务被判失败——用例一条都没执行，不是被测组件的功能缺陷。同一运行里并行的 npu_ir 编译流水线调用同样失败：x86 与 arm 两个架构的编译子任务双双失败，调用日志只留了调度层的封装信息、未留存真实编译报错；产物元数据缺失更像该编译失败导致无产物可发布的连带结果，而非下载地址配置错误。
建议: 到 npu-ir_A3_A5_compile 流水线下钻本次调用运行（run#516）两个架构编译子任务的构建日志，拿到真实编译报错并修复——调用侧日志只有调度层封装信息，定位不到编译失败点；编译修复后确认 openLiBing 产物目录正常发布，测试任务的下载即可恢复。若编排上允许编译失败先行退出，则给测试任务补一段产物前置检查：目录不存在时明确报「无产物可测」并跳过，而不是以 404 退出码把测试任务记成失败。

验证方式：复跑该流水线，要求 npu_ir 调用的两个架构编译子任务退出码为 0、测试任务能拉到 xml 元数据（日志不再出现 404）且用例执行通过，整体运行结果为 SUCCESS。
